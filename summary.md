# Summary: Medallion Architecture Cleanup

## Overview

This update simplifies the Trender data pipeline by removing three unused database tables (`raw_repo_metrics`, `stg_render_enrichment`, and `fact_render_usage`) along with their associated code. These tables were originally designed to support Render-specific enrichment features—parsing `render.yaml` files, extracting service configurations, calculating complexity scores, and detecting deploy buttons—but this functionality was never fully implemented and the tables remained perpetually empty. By removing this dead code, we've eliminated approximately 250 lines of unnecessary logic, reduced the schema from 9 to 6 tables, and streamlined the ETL pipeline to use a consistent medallion architecture (Raw → Staging → Analytics) for all repository types, including Python, TypeScript, Go, and Render projects.

The cleanup touched 21 files across the codebase, including Python ETL modules (`enrichment.py` was deleted entirely, while `extract.py`, `load.py`, and `aggregate.py` had unused functions and queries removed), database schema definitions (all three layers were updated to remove table definitions), SQL views (removed LEFT JOINs and unused analytics views), cleanup scripts (removed references from retention and truncate operations), and documentation (READMEs updated to reflect the simplified architecture). The result is a cleaner, more maintainable codebase with a single unified data flow: GitHub API responses are stored as JSONB in `raw_github_repos`, validated and cleaned into `stg_repos_validated`, then loaded into `dim_repositories` and `fact_repo_snapshots` for analytics. No testing changes are required—the workflow runs identically, just without the overhead of empty tables and unused enrichment logic.
